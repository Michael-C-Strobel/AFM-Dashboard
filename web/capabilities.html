Capabilities and validation evidence

Matrix version 0.1.0 · reviewed 2026-10-11 · roadmap card A05

Use this matrix to decide whether the workbench can read and analyze a measurement. Byte signatures select readers; filenames and successful decoding do not establish calibrated instrument compatibility. The import panel, channel warnings and exports retain configuration and unit limitations.

  • Implemented / tested: code and known-input tests support the stated subset.
  • Independently checked: recorded values match a separate reader or calculation for named fixtures. This does not certify an instrument, a physical quantity or every readable variant.
  • Readable / unverified: supported structure with a different acquisition configuration. The workbench keeps a warning visible.
  • Unsupported: no interpretation is guessed. A file is rejected, or a soundly bounded unsupported channel is omitted with an explicit reason.

Evidence paths below refer to the development repository. A local preview includes this matrix and the runtime gates, but excludes laboratory/reference binaries and development reference arrays. Preserve exact original bytes, recipe and application version for replay.

Explicit import gaps

Legacy GWYO/IBW, text or complex waves, 1D/4D IBW, generic TIFF/BigTIFF, compressed/tiled JPK or unsupported orientation/calibration, NanoScope ASCII/floating/compressed image encodings, unidentified vendors and force curves are unsupported. Formulas are retained as metadata, never executed. Importing an image from a force-capable instrument does not enable force spectroscopy. Stage rotation/origin metadata does not establish registered laboratory coordinates.

The Q02 reference program compares precisely matched methods and settings, including known mathematical inputs and Gwyddion-native examples. Next coverage work

  1. Prioritize the demonstrated lab workflow: raw/worked GWYP processing and Q02 background/step/roughness gaps. Keep manual fit-point choices explicit.
  2. Extend an existing readable instrument configuration only with evidence: X03 needs a representative source, units/orientation/masks, an independent reference and malformed-input checks. Current fixtures justify maintaining the four readers, not ranking an unseen vendor above another.
  3. Native image interchange and reusable workspaces: E02/R05 require numerical/mask round trips and source-hash verification. General lossless Gwyddion project round trips are not implemented.
  4. Force and multidimensional modes: X02/X05–X08 remain dependent on representative data, calibration and explicit physical models. An image fixture is insufficient evidence.

Maintaining this matrix

Update the matrix version, evidence paths and Kanban card when a gate or capability changes. A new fixture download alone cannot promote a configuration to validated. Preserve warnings for unknown units and omitted objects. Re-run the relevant reader/core tests and independent validator, then verify browser import/export/replay. Source identity and calibration assumptions must survive the workflow.
