# Autonomous analysis

In **Assistant**, configure the shared connection under **Ask for a plan**, refresh/inspect sources and select the permitted channels. Open **Autonomous analysis**, describe the goal and scientific constraints, choose maximum provider rounds (1–8) and local tool calls (1–64), then **Start goal**. This authorizes automatic execution within those bounds. Reviewed plans remain available separately.

Each round obtains a typed, source-bound plan, checks its hash and scope, executes it sequentially and verifies the resulting artifacts against the tool journal. Subsequent requests automatically receive compact verified observations from the latest eligible run context: acquisition quality, segmentation, texture and processing sensitivity. Surface analysis/replay claims remain a separate context (up to four steps, 32 claims). A quality-only round can therefore inform the next plan without first producing a surface claim. Each observation projection selects at most 16 completed steps and is capped at 64 KiB; the complete provider request, including history and both contexts, is capped at 256 KiB. Oversized projections reject rather than silently dropping outcomes or warnings. Raw rasters, profiles, region tables, full recipes, artifacts and journals are not transmitted. Local exports retain the full records. `list_sources` is disallowed; references must be selected sources and artifact references must point to earlier steps in the same plan. A later round can recreate a recipe but cannot directly reuse an earlier round's artifact ID. Recipe-based observations must match the exact recipe in an earlier verified analysis/replay artifact within their plan; recorded parameters and source/reference identities must match the call and selected channels.

**Pause** waits after a running local tool; **Resume** continues. **Stop** aborts an active provider request and prevents subsequent local calls. A running local numerical operation finishes and remains recorded. Provider request provenance is retained when stopped; a response that arrives while paused is audited before waiting. Download goal audit before starting another goal or reloading: it contains the selected goal, bounds, request audits, per-round manifests, verified reports and session tool journal. No credentials are exported. Each new goal has its own bounds; the underlying session also has its existing 256-call/32 MiB artifact limits.

Terminal states distinguish `evidence_returned`, `observations_returned`, `needs_input`, `budget_exhausted`, `failed` and `stopped`. Evidence returned means the model selected verified surface claims. Observations returned means it selected 1–16 distinct known observation IDs using exactly `{kind:"observations",observation_ids:[...]}`. Unknown IDs, additional values and free-form conclusions reject. Both states present recorded results, not independent proof of scientific goal achievement or calibration certification. A clarification ends the current goal; start a new goal with the missing choices. Failures stop automatically rather than retrying indefinitely. Budget exhaustion retains partial artifacts and never means success.

## Pilot SOPs

Select a [versioned pilot SOP](workflow-sops.md), read its instructions and supply required choices and deviations. Its exact instructions, ID/version, user choices and goal are captured together in the audit. Additional deviations must appear in plan rationales. Use **Expected SOP settings** before starting to record exact processing and selection choices. After execution, **Check SOP records** verifies baseline, processed output, required diagnostics and replay against the journal; the downloadable audit retains this report. Missing records remain incomplete, and even complete records require scientific and approval review. Reference reconstruction requires explicit reviewed fit points. No universal leveling rule or scientific acceptance threshold is inferred.

## Current boundaries and checks

Observation summaries retain recorded units, definitions and relevant source/support/reference warnings. Quality includes counts and boundary diagnostics; segmentation includes pixel/region counts; texture includes sampling, PSD power and ACF zero lag; sensitivity includes metric outcomes, failed alternatives, range membership and calibration/model assumptions. Full arrays and detailed region tables remain local. Candidate or region counts do not establish defect identities; sensitivity spread is not a confidence interval. Verification checks recorded integrity and binding, not independent numerical re-analysis. See the [observation contract](model-observations-design.md).

The reviewed planning UI still sends surface evidence only after explicit selection. The adapter’s optional observation input is separate; autonomous mode supplies it automatically within the authorized goal.

Existing surface-feedback tests use real synthetic local tool sessions and mocked providers: adaptive plans, scope/hash gates, budgets, pause/stop races, retained cancellation audits and secret reflection. Browser regression exercises the shared settings, two automatic plans then evidence, budget exhaustion, stop, SOP capture, audit download and mobile layout. These earlier checks do not establish validation of the observation extension. No live provider or scientific autonomous-result quality has been certified.
